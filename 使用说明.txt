本次修复（第 3 版 · 全新体检）
========================================================
你反馈的「点开 loading 一下就没内容、只有 py 那几条能出东西」，根因找到了，
是一条硬伤，跟驱动包、跟线路、跟网络都没关系：

  163 条源里有 40 条的「源类型」字段是错的（39 条压根没写，1 条写错）。
  壳就是靠这个字段决定"这条源用哪种方式去取数据"：
      type=1 → 按 JSON 接口取      type=0 → 按 XML 接口取
      type=3 → 交给驱动（jar / python / js）
  字段没写时，壳默认当成 XML 源，于是拿解 XML 的方式去解 JSON 接口
  → 一个字段都取不到 → 就是你看到的"转一下就空白"。

  你点名的「嘿嘿」正好属于这 39 条，症状完全对上。

本版改动
  · 39 条接口源补上正确类型、1 条写错的改正 → 全包 163 条字段 100% 完整
  · 41 条接口源按壳真实的请求方式端到端重跑：36 条首页/分类/详情全程出数据
    （其余 5 条是站点分类本身为空或上游 502/418，不是配置问题）
  · 96 条驱动源上游体检：81 条站点可达（403 那批是站点反爬挡机器人，正常设备能开）
  · 色播直播两个后端实测都活着，js 依赖已清零
  · 线上 131 个文件逐个对字节核对：131/131 一致

⚠️ 怎么让改动生效（重要）
  壳会把已经加载过的配置留在内存里，光换服务器上的文件、不重选是不会刷新的。
  请在壳里把这条订阅删掉，重新添加一次；或者把壳完全关掉重开。
  然后再点「嘿嘿」验证——应该立刻出片。

Zaka 成人订阅 · 自托管多线路版
========================================================

本版在「修复版」基础上，把地址做成可一键替换的，你可以整套搬到自己的
GitHub 仓库（或自己的服务器），并一次生成多条国内镜像线路，哪条通用哪条。


一、先说清楚：你说的那套方法，哪一半能用、哪一半不能用

  能用、本版已经做了的：
    · 一键把整包地址换成你自己仓库的地址（set-lines.py）
    · 一次生成多条镜像线路，壳里填能通的那条
    · 在你本机实测每条线路通不通（=你所在地的真实视角，不是我这边猜的）

  用不了的那一半（这个必须坦白）：
    · 上一版我用过「相对路径 ./jar/xxx」，想的是"换镜像不用改文件"。
      壳其实会把配置里的 "./" 自动补成完整地址，但不同分支版本的壳处理不一样，
      为了一视同仁地稳，本版所有依赖一律写成完整地址。
    · 所以本版所有依赖仍然是完整地址，只是这个地址前缀现在可以一键换成你的。


二、用法 A（最省事）：直接用现成地址

  订阅地址（已经在线上，验过能拉到内容）：

    https://r18sub.web.zaka.live/index.json

  不用下载任何文件，填进壳里即可。这条随时可用，下面自托管那套是可选项。


三、用法 B（推荐，不依赖任何人）：搬到你自己的 GitHub

  1) 新建仓库，勾 Public（私有仓库镜像拉不到）
  2) 把压缩包里的全部内容解压出来
  3) 在仓库页面 Add file → Upload files，把 index.json、live.m3u、
     live-p2p.m3u、README.md、使用说明.txt、set-lines.py、check-lines.html
     以及 jar / json / lib / js / plugin / live / tv / XYQHike 这些文件夹
     一起拖进去（目录结构别改），提交

     命令行方式：
       git init && git add . && git commit -m "init"
       git branch -M main
       git remote add origin https://github.com/<用户名>/<仓库名>.git
       git push -u origin main

  4) 生成线路订阅（在你电脑上跑，需要 python3）：

       cd 这个目录
       python3 set-lines.py --check                    # 先看你那边哪条通
       python3 set-lines.py --mirror                   # 用推荐线路生成一套
       python3 set-lines.py --mirror all               # 全部线路都生成
       python3 set-lines.py --mirror ghproxy ghfast    # 只生成指定线路

     没配 git remote 就手动指定：
       python3 set-lines.py 你的用户名 你的仓库名 main --mirror

  5) 生成出来的 index-<线路>.json 全部 push 上去，然后在壳里填能通的那条，例如：
       https://gh-proxy.com/https://raw.githubusercontent.com/你/仓库/main/index-ghproxy.json
       https://raw.githubusercontent.com/你/仓库/main/index-raw.json

  脚本会自动自检：替换了多少处引用、有没有残留旧地址、引用的文件包内是否齐全。
  正常输出长这样（223 处引用、零残留、零缺失）。


四、不知道自己那边哪条线路通？两个办法

  办法一（手机就能用，最推荐）：
    浏览器打开   https://r18sub.web.zaka.live/check-lines.html
    填上你的用户名和仓库名，点「开始实测」。
    十几秒后每条线路会标出：通 / 不确定 / 不通 / 超时，并给出可直接复制的地址。

  办法二（电脑上）：
    python3 set-lines.py --check

  ⚠️ 我这边测出来的结果只能当参考（我是从境外线路测的），国内各家运营商
     情况不一样。以你自己实测（--check 或上面那个网页）为准。


五、用法 C：换到自己的服务器 / 任何静态托管

    python3 set-lines.py --base https://你的域名/sub/

  生成 index-custom.json，整包依赖都指向你这个地址。
  （顺带一提：整个目录结构要原样放到该地址下，index.json 引用的
   jar / json / js / plugin / lib / live / tv / XYQHike 都在子目录里。）


五之二、当前我这边实测的线路情况（境外视角，仅参考）

  通的（按当时测得的速度排）：
    官方 raw            392ms     无中间层，国内不一定通
    jsDelivr 主入口      729ms     有缓存，更新后可能要等

    gh-proxy.com        764ms     ← 国内常用
    Cloudflare 节点      802ms
    gh.llkk.cc          815ms

    bgithub             1085ms

  ⚠️ 镜像站自己会挂、会限流，今天通明天断很正常。断一条换下一条就行，
     这也是为什么建议一次生成多条线路。


六、注意事项

  · 仓库必须是 Public，私有仓库所有镜像都拉不到。
  · 分支名要和地址里一致：地址写 /main/，仓库默认分支就得是 main。
  · 整套文件一起传，目录结构别动（依赖都在子目录里）。
  · jsDelivr 系有缓存，你更新了仓库它可能还给你旧文件；
    想立刻生效就加 commit 号： python3 set-lines.py --at <commit号> --mirror
  · 中文文件名已全部改成英文（zone1.json / heiliao.py 这类），
    中文路径经过镜像时编码各家不一样，容易 404 —— 这是上一版就修掉的坑。
  · 所有文件 UTF-8、无 BOM。
