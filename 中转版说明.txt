【先说实话：为什么必须挂梯子】

我把整包里的 133 个上游域名逐个解析、逐个查归属，结果是 —— 0 个在国内。

    105 个挂在 Cloudflare 后面
    其余分散在 美 / 法 / 荷 / 港

所以"所有源都要挂梯子才能出数据"不是规则写错了，也不是配置问题：
这些站根本不在墙内，任何壳、任何规则都变不出数据。

但"每台设备都得挂梯子"这件事可以免掉 ——
找一台墙外的机器当中转（relay），壳里所有请求先发给它，它再去取。
盒子/电视/手机只认这一个地址，不用装任何梯子客户端。

    盒子 ──(国内直连)──> 中转机 ──> 上游站点
                        ▲
                   中转机在墙外，它自己能访问上游


────────────────────────────────────────
一、中转机从哪来（三选一）
────────────────────────────────────────

▍方案 A：一台海外小鸡（最省心，推荐）

  1 核 1G 就够跑服务；带宽越大越好（播放走中转要吃流量）。
  任意一家海外 VPS 都行，装好系统直接用，不用装任何额外软件
  （relay.py 只用 Python 标准库，系统自带的 python3 就能跑）。

▍方案 B：家里一台常开的电脑 / 软路由 / NAS（本身挂着梯子）

  relay 跑在这台机器上，它的出站走你自己的梯子，
  盒子指向它的**局域网地址**（例如 http://192.168.1.10:8899）。
  这是"已经买了梯子、但电视盒子装不了客户端"最省钱的用法。
  ⚠ 这种情况 --public-base 要填局域网地址，别填 127.0.0.1。

▍方案 C：不折腾中转，直接在盒子上挂梯子

  如果你路由器已经是全局模式，盒子上什么都不用改，本方案可以不用。


────────────────────────────────────────
二、部署中转（两条命令）
────────────────────────────────────────

1) 把 relay/relay.py 传到你那台中转机上（放哪都行）

2) 跑起来（把 IP 和口令换成你自己的）：

     python3 relay.py -p 8899 --public-base http://你的中转机IP:8899 --token 自己设个口令

   想后台常驻：

     nohup python3 relay.py -p 8899 --public-base http://你的中转机IP:8899 \
            --token 自己设个口令 > relay.log 2>&1 &

   想开机自启（systemd，存成 /etc/systemd/system/zaka-relay.service）：

     [Unit]
     Description=Zaka Relay
     After=network.target

     [Service]
     ExecStart=/usr/bin/python3 /root/relay.py -p 8899 --public-base http://你的中转机IP:8899 --token 你的口令
     Restart=always
     RestartSec=3

     [Install]
     WantedBy=multi-user.target

     systemctl enable --now zaka-relay

3) 验证中转是活的：

     在手机或电脑浏览器打开：  http://你的中转机IP:8899/
     返回 {"ok": true, ...} 就成了。

     再实测一条真实源（把口令和 IP 换成你的）：

     curl -s "http://你的中转机IP:8899/你的口令/https/51avtv.com/vod" | head -c 200

     能看到 HTML 就是通了；返回 407 = 口令不对；连不上 = 端口没放行
     （记得在云厂商安全组 + 机器防火墙里放行 8899）。


────────────────────────────────────────
三、把整包切过去（一条命令）
────────────────────────────────────────

在解压出来的包目录里跑：

     python3 set-relay.py --base http://你的中转机IP:8899 --token 你设的口令

它会自动改好这些地方：

  · 42 条采集接口           → 改成走中转
  · 43 条 py 引擎规则        → 写入中转开关（相对链接拼接不会错）
  · 44 条 jar 规则           → 规则里写死的网址换成中转地址
  · 20 个 py 插件            → 接入中转（代理方式，不动插件本身的网址）
  · 色播直播 / 佳丽直播      → 取数与播放地址都走中转
  · 直播 m3u 列表            → 地址换成走中转

然后整个包传到你的仓库（目录结构别改），壳里**删掉旧订阅重新添加一次**
（壳会把配置缓存在内存里，不重加不生效）。

   只想先看看会改哪些东西：  加 --dry-run
   播放不走中转（省流量）：  加 --no-media    ← 只中转列表和接口
   直播列表也不动：          加 --no-live


────────────────────────────────────────
四、几点要拎清的
────────────────────────────────────────

▍流量

  默认「播放也走中转」，好处是盒子端完全不用梯子；
  代价是中转机替你扛视频流量（一部片 1~3G）。
  小鸡流量吃紧就加 --no-media —— 列表/详情/搜索走中转，
  播放仍由盒子直连（这时播放那一步还得靠梯子或不挂梯子的线路）。

▍口令

  建议一定加 --token。不加，中转机就是个谁都能用的公开代理，
  IP 很容易被别人拿去刷、被机房警告。加了口令再配个非常规端口更稳。

▍稳妥性

  引擎遇到中转不通会**自动回退直连**，不会把站点解析成空白。
  中转机挂了也就是回到"要挂梯子"的状态，不会更糟。


────────────────────────────────────────
五、还原
────────────────────────────────────────

     python3 set-relay.py --restore

所有被改过的文件原样都在同目录的 *.relaybak 里，一条命令全部退回直连。


────────────────────────────────────────
六、覆盖不到的部分（这个中转解决不了）
────────────────────────────────────────

  · JS 反爬挑战站：苹果av / 台湾kiss / 18jtv —— 站点要求先跑 JS 拿令牌，
    脚本层过不去，跟中不中转无关
  · 源站自己挂了：域名过期、源站宕机、域名被接管的那些（详见 修复说明.txt）
  · Cloudflare 强校验站：AirAV / 300分类 / 444咖啡 / PornLuLu / javtsunami
  · 中转机所在线路被墙或限速：换机器、换端口、换机房

  另外：中转只解决"能不能取到数据"，站点本身在改版 / 挂了，中转也变不出来。
