【这一版是干嘛的】

上一版（规则源修复版）的订阅地址指向托管服务器，国内直连能用。
你之前要过的那种「放到自己 GitHub、走国内镜像加速」的版本，上几轮漏做了，
这版补上——整站还是同一份内容（153 条点播源 + 24 路品牌成人台 +
96 份规则 + 色播直播全量数据），但引用方式换成了**相对路径**，
所以不管你用哪家镜像地址，依赖文件都会自动跟着走。

  ⚠ 源内容跟上一版一模一样，只是"怎么访问"换了。你如果托管地址用得
     好好的，不用折腾。这版是给"不想依赖我这边、要自己掌控"的场景。

────────────────────────────────────────────────────────
二、这包跟上一版的结构差异
────────────────────────────────────────────────────────

  · index.json 里 205 处依赖引用，全部从「绝对地址」改成「相对路径」
    （"./jar/xxx.jar" 这种写法）。
    好处：你填 gh-proxy 的地址，依赖就走 gh-proxy；你填 jsdelivr 的地址，
    依赖就走 jsdelivr。一条订阅地址通吃所有镜像，不用改文件。

  · 多了一个 index.html：本地打开（或开 GitHub Pages）就是一个地址生成器，
    填一次「用户名/仓库名」，下面六条镜像地址全自动出来，点一下就复制。

  · 多了一个 set-base.py：只有"你的壳不认相对路径"时才需要它，
    一条命令把整包换成绝对地址，跑完自带自检。
    （用法：python3 set-base.py --repo 用户名/仓库名）

  · 文件名全英文、编码全 UTF-8 无 BOM——这两点是国内镜像加载失败的头号原因，
    已经逐个核过：361 个文件，零中文名、零 BOM。


────────────────────────────────────────────────────────
三、部署到你的 GitHub（三步）
────────────────────────────────────────────────────────

  1. 新建仓库，勾 Public（私有仓库镜像拉不到）

  2. 把本包解压后的**全部内容**传上去
     注意：所有文件夹（rules / py / sebo / jar / json / lib / js /
     plugin / XYQHike / live / tv）都要传，目录结构别改。

  3. 订阅地址填下面任意一条（把「用户名/仓库名」换成你自己的）：

     https://gh-proxy.com/https://raw.githubusercontent.com/用户名/仓库名/main/index.json
     https://ghproxy.net/https://raw.githubusercontent.com/用户名/仓库名/main/index.json
     https://gh.llkk.cc/https://raw.githubusercontent.com/用户名/仓库名/main/index.json
     https://ghfast.top/https://raw.githubusercontent.com/用户名/仓库名/main/index.json
     https://fastly.jsdelivr.net/gh/用户名/仓库名@main/index.json
     https://cdn.jsdmirror.com/gh/用户名/仓库名@main/index.json

  分支名要跟地址里的 /main/ 对上（GitHub 新建仓库默认就是 main，
  老仓库可能是 master，看你仓库首页那行字）。

────────────────────────────────────────────────────────
五、什么时候需要跑 set-base.py
────────────────────────────────────────────────────────

  症状：换完之后，大部分源正常，但**需要加载 jar / 脚本的那一批源全白**
      （比如那些"㊙️"开头的规则源）。

  这说明你的壳不认相对路径。跑这个（30 秒）：

      python3 set-base.py --repo 用户名/仓库名

  想换别的镜像加个参数，比如：

      python3 set-base.py --repo 用户名/仓库名 --mirror ghfast
      python3 set-base.py --repo 用户名/仓库名 --mirror jsdelivr

  用自己的域名：

      python3 set-base.py --base https://你的域名/订阅目录

  不带参数跑就是"检查模式"，先看有多少处要换，不改任何文件。


────────────────────────────────────────────────────────
六、常见问题
────────────────────────────────────────────────────────

  Q：镜像地址和托管地址，我该用哪个？
  A：先用托管地址（最省事）。想自己掌控、或者托管那边出问题时，
     再用 GitHub + 镜像这套。两边内容一样。

  Q：为什么不用把相对路径改成固定网址？
  A：改了就被绑死在某一家镜像上，那家挂了你就得重改一遍。
     相对路径是"谁访问就跟着谁走"，一条通吃。

  Q：更新怎么办？
  A：新的文件覆盖上去就行。壳那边删掉订阅重新添加一次最保险。

  Q：要不要挂梯子？
  A：不用。数据全在你自己的仓库里，走的是国内镜像。

  Q：色播直播那条走的什么？
  A：它是 py 源，数据在包的 sebo/ 目录里（136 个平台）。
     注意：相对路径模式下，色播直播这条仍然读托管站的数据。
     想让它也完全走你自己的地址，跑一次上面第五节的 set-base.py 就行。

  【关于源本身的问题】
   · 站点自己的列表页掺广告条目，点进去是广告跳转——源站的问题，屏蔽不掉，
     往下翻正常条目都能播。
   · 被移除的那 9 条源（Aries / 爱色吧 / 四区 / SOAV / 国产麻豆 / 奶妃 /
     色花堂 / 女优色库 / 51短剧）是源站自己停了，恢复了我随时加回来。
   · 哪条点开还是白的，把名字发我，我按名字去对。
